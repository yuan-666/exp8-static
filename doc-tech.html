技术文档

项目背景

校园活动管理系统旨在为高校师生提供便捷的校园活动发布、浏览与报名平台。传统方式下，校园活动信息通过海报、QQ群等分散渠道传播，存在信息不对称、报名流程繁琐、管理效率低等问题。

本系统通过 Web 应用集中管理活动信息，实现活动的在线发布、搜索、报名与统计，有效提升校园活动的组织效率和参与体验。

核心目标

  • 提供直观的活动浏览与搜索体验
  • 简化报名流程，一键报名/取消
  • 管理员高效管理活动与报名人员
  • 响应式设计，多终端适配
  • 纯静态部署，零服务器成本

技术选型理由

  • HTML/CSS/JS：无构建依赖，直接部署至 GitHub Pages
  • Bootstrap 5.3：成熟的响应式框架，快速构建 UI
  • localStorage：浏览器本地存储，模拟后端数据持久化
  • Glassmorphism：现代设计风格，提升视觉层次感

关键实现细节

  • 认证流程：登录时将用户对象存入 localStorage.currentUser，页面加载时检查该值决定跳转
  • 权限控制：requireAuth() 和 requireAdmin() 在页面初始化时调用，未授权自动跳转
  • 导航栏渲染：每个页面通过 renderNavbar() 动态生成，根据登录状态和角色显示不同内容
  • 活动报名：通过 registerForActivity() 修改 registrations 数组，实时更新进度条
  • 搜索排序：前端过滤和排序，Array.filter() + Array.sort()

并发与难点

数据一致性问题

由于使用 localStorage 存储数据，在多标签页同时操作时可能出现数据不一致：

  • 问题：标签页 A 报名后，标签页 B 的数据未更新
  • 解决方案：监听 storage 事件，当其他标签页修改 localStorage 时触发数据刷新
window.addEventListener('storage', function(e) {
  if (e.key === 'activities' || e.key === 'registrations') {
    renderActivities(); // 重新渲染
  }
});

报名名额竞争

在名额有限的情况下，并发报名可能导致超额：

  • 问题：多个请求同时读取剩余名额，均判断可报名
  • 解决方案：前端使用乐观锁机制——报名前重新读取最新数据，写入前再次校验
function registerForActivity(userId, activityId) {
  const regs = getRegistrations();        // 读取最新数据
  const activity = getActivityById(activityId);
  const count = getParticipantCount(activityId);
  if (count >= activity.maxParticipants)   // 再次校验
    return false;
  // ... 写入
}

其他技术难点

  • 毛玻璃兼容性：backdrop-filter 在旧浏览器不支持，添加 -webkit- 前缀和降级背景色
  • 图片占位：使用 picsum.photos 随机图片，需处理加载失败的情况
  • 表单验证：HTML5 原生验证 + JS 自定义验证，双重保障
  • SEO 优化：静态页面无 SSR，通过语义化 HTML 和 meta 标签弥补

数据库设计

系统使用 localStorage 模拟关系型数据库，共 3 张表：

用户表 (users)

字段类型说明
idNumber主键，自增
usernameString用户名，唯一
passwordString密码（明文存储，仅演示）
nicknameString昵称
phoneString手机号
roleNumber角色：0=学生，1=管理员
avatarString头像 URL
createdAtString注册时间

活动表 (activities)

字段类型说明
idNumber主键，自增
titleString活动标题
descriptionString活动描述
locationString活动地点
startTimeString开始时间
endTimeString结束时间
imageString封面图 URL
maxParticipantsNumber最大人数
contactString联系方式
statusString状态：upcoming/full/ended
createdAtString发布时间

报名记录表 (registrations)

字段类型说明
idNumber主键，自增
userIdNumber外键 → users.id
activityIdNumber外键 → activities.id

ER 关系

users  1 ──── N  registrations  N ──── 1  activities
